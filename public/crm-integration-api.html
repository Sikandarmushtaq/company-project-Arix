CRM Integration API

Sync call outcomes into your CRM — in real time over signed webhooks, and on demand through a reconciliation API. Both carry the same disposition data, keyed by a call id.

Base URL
https://api.sufitravel.nuxcall.com
Timestamps
ISO 8601 · UTC
Phone format
digits only, no +

Overview

Two complementary channels keep your CRM in step with what agents do on the phone.

Push

Webhook

Nuxcall sends a signed event the moment an agent sets a call outcome. Use it to update your CRM in real time.

Pull

Reconciliation API

Query Nuxcall for dispositions on demand — backfill history or catch anything a webhook delivery missed.

Every disposition is identified by a callId, so your CRM can match each outcome to the right lead and agent. Use the webhook as the primary path and the pull API as a safety net.

Getting set up

Your account administrator configures the integration from the dashboard (Admin → CRM Webhook). During setup you receive two credentials.

Signing secretVerifying webhook signaturesShown once at setup. Store securely.

Your administrator also registers your webhook endpoint URL (must be https:// on a public host) and can choose to receive all dispositions or only audit-flagged ones.

Verifying the signature

Every request includes X-Nuxcall-Signature: t=<timestamp>,v1=<hmac>. The v1 value is a hex HMAC-SHA256 of `${t}.${rawBody}` using your signing secret. Recompute it over the raw request body and compare in constant time.

Node.js
const crypto = require('crypto');

function verify(rawBody, signatureHeader, secret) {
  const parts = Object.fromEntries(
    signatureHeader.split(',').map((kv) => kv.split('='))
  ); // { t, v1 }
  const expected = crypto
    .createHmac('sha256', secret)
    .update(`${parts.t}.${rawBody}`)
    .digest('hex');
  const a = Buffer.from(expected), b = Buffer.from(parts.v1 || '');
  return a.length === b.length && crypto.timingSafeEqual(a, b);
}
Python
import hmac, hashlib

def verify(raw_body: bytes, signature_header: str, secret: str) -> bool:
    parts = dict(kv.split("=", 1) for kv in signature_header.split(","))
    expected = hmac.new(
        secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, parts.get("v1", ""))

Delivery semantics

  • Respond with a 2xx quickly (within 8 seconds); do heavy work after acknowledging.
  • Nuxcall retries up to 3 times with backoff on a non-2xx, timeout, or network error.
  • Delivery is at-least-once — the same event may arrive twice. Treat callId as the key and upsert (a re-disposition sends a fresh event with the latest outcome).
  • Retries cover transient failures, not an extended outage on your side. Use the pull API to reconcile.

Pull API

Query dispositions on demand — for backfill or to catch missed webhooks.

GET https://api.sufitravel.nuxcall.com/api/v1/crm/dispositions

Authentication

Send your API key in either header. Requests without a valid key return 401.

HTTP
X-Api-Key: nxk_your_key_here
# — or —
Authorization: Bearer nxk_your_key_here

Query parameters

ParamTypeDefaultDescription

Results are ordered oldest-first, so you can page forward and advance since to the createdAt of the last item you processed.

Integration flow

A recommended end-to-end path.

  1. Stand up an HTTPS endpoint and give the URL to your account administrator.
  2. Store the signing secret and API key securely.
  3. On each webhook: verify the signature, return 2xx immediately, then upsert by callId.
  4. Run a periodic pull with since = the last createdAt you stored, to reconcile gaps.
  5. Match each event to a lead by the caller / callee phone number, and use callId to de-duplicate.

Best practice: the webhook is your real-time path; the pull API is the safety net. Running both makes the sync resilient to any single delivery failure.
